# BREGIS COACH

Локальная образовательная платформа по Брегис, WebLab и TLA. Рабочая папка: `C:\Users\user\Desktop\Trener\Project\Bregis-COACH`.

## Важное ограничение

**Никаких push, PR, публикаций, GitHub Actions и изменений Neon до отдельного согласования пользователя после локальной проверки.** Разрешение на push не означает разрешения на публичный хостинг или миграции production.

## Запуск

Требуется Node.js 24. После `npm ci` выполните `npm run build`, затем `npm start`. Сайт доступен только на `http://localhost:4317`. По умолчанию используется локальная SQLite в `.local/coach.sqlite`, данные сохраняются между запусками. Это окружение разработки; production без PostgreSQL не запускается.

Вход → «Открыть локальный профиль» создаёт локального проверочного пользователя с правами администратора. Этот маршрут отключён при PostgreSQL и в production, а локальный пользователь исключён из рейтингов. Настоящих игроков и фиктивных рейтингов нет.

`npm test` — расчёт баллов, уровни, идемпотентность XP, откат транзакций, поиск и HTTP-сценарии.

`npm run build` — оптимизированная клиентская сборка. После изменения исходников повторите сборку; после изменения сервера перезапустите `npm start`.

## Neon PostgreSQL

GitHub Secret `DATABASE_URL` существует, но его значение невозможно скачать через GitHub Secrets API. Для локальной проверки интеграции нужен собственный `.env` с подключением к изолированной dev-базе. Не печатайте строку в логи и не добавляйте в Git.

1. Скопируйте `.env.example` в `.env` и заполните `DATABASE_URL` и прямое `DATABASE_URL_UNPOOLED`.
2. Убедитесь, что это изолированное окружение разработки. Только после этого задайте `CONFIRM_DEV_DATABASE=yes` и выполните `npm run db:migrate`.
3. `node --env-file=.env scripts/refresh-catalog.mjs` импортирует материалы как черновики для PostgreSQL. Опубликованность локального каталога не является разрешением публикации во внешней среде.

Для локального SQLite поиск использует FTS5 Unicode/prefix. Для PostgreSQL — `tsvector`, русский словарь, `websearch_to_tsquery` и GIN. Полноценная русская морфология проверяется отдельно после предоставления dev-окружения PostgreSQL.

Миграции сохраняются в `migrations/`, повторный запуск безопасен. Схема и импорт проверены на отдельной ветке Neon bregis-deploy-validation.

## Учётные записи

Регистрация и вход используют имя (3–40 букв, цифр, `_`, `-`, без учёта регистра) и пароль длиной 10–128 символов. Пароли хранятся в виде scrypt-хешей с индивидуальной случайной солью. Cookie сеанса — HttpOnly, SameSite=Lax, Secure в production. Формы защищены проверкой Origin, число попыток ограничено.

В кабинете можно изменить пароль, указав текущий. Версия учётных данных увеличивается, старые сеансы перестают проходить авторизацию. Имя для входа не меняется при изменении отображаемого имени. Самостоятельное восстановление забытого пароля пока не реализовано. Новые пользователи получают только роль user; назначение admin выполняется владельцем через защищённый доступ к базе после проверки конкретного аккаунта.

## Внешний запуск

Публикация сайта разрешена пользователем 28.09.2026. Railway собирает Dockerfile из main. Необходимы NODE_ENV=production, PORT=8080, APP_URL с точным HTTPS-адресом, случайный SESSION_SECRET (32+ символов), DATABASE_URL Neon, CONTENT_PUBLICATION_APPROVED=yes и CONFIRM_DEPLOY_DATABASE=yes.

Docker-сборка получает согласованный комплект материалов по манифесту data/content-release.json и проверяет SHA-256. Перед запуском scripts/prepare-deployment.mjs транзакционно применяет миграции и добавляет отсутствующие статьи/квесты; существующие аккаунты, прогресс и редакторские изменения сохраняются. Для миграций используется прямое подключение Neon, для приложения допустимо pooled-подключение. Проверка готовности: /api/health.

Секреты хранятся только в настройках хостинга, не в Git и не в клиентской сборке. Для отката кода используйте предыдущий успешный deployment Railway; не откатывайте базу с удалением пользовательского прогресса.

## Редактору

Через «Управление контентом» можно искать статьи, создавать черновики, редактировать текст, менять направление и состояние, публиковать/архивировать. Предыдущая версия сохраняется в `article_versions`, действия фиксируются в `audit`; конфликтующие изменения отклоняются.

«Практики и банк вопросов» позволяет редактировать вопросы, варианты, порядок/множественные ответы, пояснения, ссылки на опубликованные материалы, XP и состояние. Вопрос из DOCX сначала создаётся черновиком. Перед сохранением сервер проверяет ключ ответов и наличие источника. Старые попытки сохраняют снимок вопросов своей версии.

Роль редактора не может публиковать; публикация доступна администратору. Все права проверяются сервером. Первичная локальная учётная запись предназначена исключительно для проверки интерфейса.

## Правила обучения

За изучение статьи сохраняется отметка без XP. Она не подтверждает знание. Квест при результате от 80% даёт фиксированную награду, однократно за его версию. Начисление защищено транзакцией и уникальностью `(user_id, source)`. Повторные попытки разрешены, но повторный XP за ту же версию исключён.

Уровень: `floor(sqrt(XP / 100)) + 1`. Пороги: 0, 100, 400, 900 XP. Достижения: первая завершённая практика, 5 прочитанных материалов, 300 XP, 3 завершённые практики. Это учебные показатели, а не профессиональная сертификация.

Рейтинг добровольный, email скрыт. Период месяца считается по UTC. При равном XP применяется стабильный порядок по идентификатору. Личный кабинет предоставляет экспорт и удаление собственных данных.

## Безопасность и эксплуатация

Сервер слушает только `127.0.0.1`. Применены CSP/Helmet, ограничения частоты/размера запросов, same-origin проверка изменений, HttpOnly/SameSite сессии, Secure cookie в production, очистка HTML и параметризованные запросы. Ключи ответов находятся на сервере до завершения попытки. Логи ошибок содержат тип ошибки и request ID без SQL, токенов и исходных данных.

Все анимации отключаются при `prefers-reduced-motion`. Шрифты Russo One и IBM Plex Mono находятся локально. Логотип — прозрачная лиса из предоставленного изображения, надпись BREGIS набрана отдельно.

Перед публичным размещением обязательны: проверка PDF/скриншотов на персональные данные, подтверждение права распространения источников, настройка реальных OAuth/Neon, проверка PostgreSQL-миграций и адаптация хранения файлов к хостингу. Без `CONTENT_PUBLICATION_APPROVED=yes` production не запускается. Это дополнительный технический барьер, а не замена явного разрешения пользователя.

## Резервное копирование

Остановите локальный сервер, затем скопируйте `.local/coach.sqlite` и `data/`, `public/media/`, `public/manuals/` в защищённую папку. Не копируйте активный SQLite-файл без его WAL. Восстановление: остановить сервер, восстановить комплект, запустить и проверить `/api/health`.

Для PostgreSQL используйте `pg_dump` через прямое подключение и проверьте `pg_restore` в отдельной базе. Производственные миграции и восстановление выполняются только после согласования. Миграции 001/002 добавляют схему и индекс; автоматический разрушительный rollback не предусмотрен.

## Текущая учебная структура

- `/#quests`: 206 тематических квестов по руководству и 16 дополнительных практик; в каждом 3–10 заданий, объяснения и ссылки на источники. `data/curriculum.json` связывает квесты с разделами документа. Короткие вводные темы включают контекст подразделов.
- `/#games`: шесть пошаговых дел — приём заказа, оборудование, отслеживание материала, непринятые ответы, сортер и контроль качества. Есть сборка последовательностей, практический ввод IDS и разбор ошибок.
- `/#weblab`: самостоятельный справочник из 63 инструкций WebLab. Общий раздел «База знаний» заменён справочником; старые ссылки на статьи Лаборатории переводят в непрерывный документ.
- `/#search`: статьи WebLab и позиции в Руководстве ЛИС. Индекс документа хранится локально в `data/manual-search.json`.
- `/#manual/lab/13`: «Руководство ЛИС», непрерывный документ с оглавлением из 581 пункта, переходами к заголовкам и автоматической подсветкой по прокрутке. Обложка и колонтитулы скрыты; текст и иллюстрации оригинала сохранены. PDF.js и worker загружаются локально.
- `/#lab-game`: 10 моделей анализаторов, пять отделов, реестр ICM с назначенными портами. Параметры обмена основаны на связанных инструкциях Redmine. Адрес сервера, порты, адреса MOXA, длительности измерений и трек — условия симуляции. Реальных сетевых соединений игра не открывает.
- В игре нет готового паспорта с ответами: инженер сверяет настройки по ссылке на статью. Неисправности возникают не чаще раза в 150 игровых секунд, не более одной одновременно. Восстановление — выбор подходящего решения с пояснением; штрафов за ошибки нет, пробирки сохраняются.
- Очки игры: +25 за первое подключение, +15 за выдачу, +50 за случайную аварию, разовые бонусы +100/+250 за 10/50 выданных. Учебные аварии очков не дают. Очередь до 120 пробирок; при переполнении приём приостанавливается. Очки игры отделены от рейтингового XP.

## Что включено в репозиторий

В Git включены исходный код, миграции, тесты, учебные задания, обезличенные профили симулятора, логотип и метаданные источников. Секреты и рабочая база SQLite не включены.

**Свежий clone не содержит закрытый комплект учебных материалов.** PDF, изображения инструкций, импортированный каталог статей, полный текстовый индекс документа и исходный банк DOCX остаются локальными и исключены через `.gitignore`. Без них игра и интерфейс доступны, но руководство и импортированные статьи не будут заполнены.

Для полного локального запуска нужен разрешённый комплект `data/catalog.json`, `data/manual-search.json`, `public/manuals/` (включая `lab-toc.json`), `public/media/` и при необходимости `data/question-drafts.json`. Копируйте его по защищённому каналу, затем выполните `node scripts/refresh-catalog.mjs` и `node scripts/refresh-quests.mjs`. Не используйте для этого production DATABASE_URL.

Проверки содержимого и HTTP-сценариев в `npm test` требуют этого локального комплекта. Проверены 34 теста и production-сборка. При подключённом Railway push в main запускает сборку и настроенные миграции.
