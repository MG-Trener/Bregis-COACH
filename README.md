# BREGIS COACH

Образовательная платформа для пользователей и инженеров лабораторных информационных систем Брегис. Руководства с исходными иллюстрациями, тематические квесты, практические тренажёры и игра по подключению анализаторов — в едином киберпанк-интерфейсе.

Материалы можно изучать без регистрации. Учётная запись нужна для сохранения результатов квестов, получения XP и участия в рейтинге.

## Состояние проекта

На 28 сентября 2026 года:

- Локальная версия реализована; исходный код опубликован в этом репозитории.
- Проверены 34 автоматических теста и сборка для production.
- Добавлены регистрация по имени и паролю и смена пароля в кабинете. Google OAuth для входа не требуется.
- Миграции и импорт материалов проверены на отдельной тестовой ветке Neon PostgreSQL 18.
- Конфигурация Railway подготовлена, но **работающая внешняя версия ещё не запущена**. Подключение репозитория к сервису не завершено; создание дополнительного сервиса ограничено бесплатным тарифом.
- Архив материалов, указанный в `data/content-release.json`, ещё не опубликован. Его размещение в публичном GitHub Release требует отдельного подтверждения. До этого Docker-сборка, загружающая архив, не сможет завершиться.

### Как устроена практика

За квест начисляется XP при результате от 80%, один раз за версию квеста. Повторные попытки разрешены. Изучение статьи сохраняет отметку о прочтении без начисления XP. Уровень рассчитывается как `floor(sqrt(XP / 100)) + 1`.

Участие в рейтинге включается пользователем добровольно. Месячный период считается по UTC. Учебные результаты не являются профессиональной аттестацией.

В игре инженер сверяется с инструкциями анализаторов в Redmine; доступ к этим внешним страницам может требовать отдельной авторизации. Адреса, порты и время обработки — условия симуляции, реальных подключений к ЛИС нет. Неисправности возникают не чаще одного раза в 150 игровых секунд и не накладываются друг на друга. Неверный выбор ремонта не отнимает очки и не уничтожает пробирки.

**Смена в игре сохраняется в браузере.** Её очки отделены от серверного XP и рейтинга квестов.

## Быстрый локальный запуск

Требуется **Node.js 24** с npm. Команды выполняются из корня проекта.

```sh
git clone https://github.com/MG-Trener/Bregis-COACH.git
cd Bregis-COACH
npm ci
npm run build
npm start
```

Откройте [http://localhost:4317](http://localhost:4317). Без `DATABASE_URL` приложение использует SQLite в `.local/coach.sqlite`; схема создаётся автоматически. При наличии локального каталога сервер добавляет отсутствующие материалы и квесты.

**Свежий clone не содержит полного комплекта инструкций.** Интерфейс и симулятор доступны, но для руководств, статей, иллюстраций и проверок содержимого нужны файлы из следующего раздела.

Для собственных настроек скопируйте [`.env.example`](.env.example) в `.env`. Оставьте `DATABASE_URL` пустым для SQLite. Укажите постоянный случайный `SESSION_SECRET`, если нужно сохранять действующие сеансы между перезапусками; без него локальный сервер генерирует новый секрет при каждом старте.

Для проверки административного интерфейса в форме входа есть кнопка **«Локальный проверочный профиль»**. Она доступна только при локальной SQLite и отключена в production и при PostgreSQL. Этот профиль не участвует в рейтинге.

После изменений клиента повторите `npm run build`. После изменений сервера перезапустите `npm start`. `npm run dev` использует тот же сервер: Vite в режиме разработки подключается, только если отсутствует `dist/index.html`.

## Учебные материалы

Исходные документы сохраняются отдельно от кода. Для полного локального экземпляра разместите разрешённый комплект по следующим путям:

| Путь | Назначение |
| --- | --- |
| `data/catalog.json` | Тексты статей, структура, ссылки на источники и изображения. |
| `data/manual-search.json` | Текстовый индекс страниц руководства для общего поиска. |
| `public/manuals/lab.pdf` | Руководство «Брегис Лаборатория». |
| `public/manuals/tla.pdf` | Инструкция лейкосчётчика TLA. |
| `public/manuals/lab-toc.json` | Оглавление с позициями заголовков. |
| `public/media/` | Изображения из инструкций. |
| `data/question-drafts.json` | Необязательный банк черновиков из DOCX для редактора. |

При обновлении существующей локальной SQLite выполните:

```sh
node --env-file-if-exists=.env scripts/refresh-catalog.mjs
node --env-file-if-exists=.env scripts/refresh-quests.mjs
```

Эти команды предназначены для локального рабочего комплекта; не задавайте для них production-подключение. Обновление каталога сохраняет отредактированные статьи с версией выше 1, а обновление квестов сохраняет историю попыток и XP.

### Источники и ограничения

- Руководство «Брегис Лаборатория» от 30.06.2026 — 331 страница.
- Пользовательская инструкция лейкосчётчика TLA — 23 страницы.
- Redmine WebLab — 63 страницы; при импорте раскрыты 159 блоков, включая вложенные. Отчёт: [`data/source-import-report.json`](data/source-import-report.json).
- DOCX программы тестирования — 61 исходный вопрос. В документе нет отмеченного ключа ответов, поэтому этот банк требует редакторской проверки перед публикацией.

Иллюстрации привязаны к соответствующим темам. Связи с оригиналами записаны в [`data/image-provenance.json`](data/image-provenance.json). Одно изображение источника (`payment_dialog.png`) недоступно; отсутствие отмечено в статье.

PDF, импортированные изображения, каталог, поисковый индекс, рабочая база и секреты исключены из Git. Право на распространение исходных материалов не следует из доступности кода. Перед внешним размещением проверьте права на материалы и наличие персональных или служебных данных. Команды и SQL из инструкций являются учебным содержимым, а не действиями, которые нужно выполнять при установке сайта.

## Учётные записи и безопасность

Имя для входа содержит 3–40 букв, цифр, символов `_` или `-`; регистр не учитывается. Пароль — от 10 до 128 символов. Отображаемое имя можно изменить отдельно от имени для входа.

Пароли хранятся как scrypt-хеши с индивидуальной случайной солью. Смена пароля требует текущего пароля и делает остальные сеансы недействительными. **Автоматическое восстановление забытого пароля пока не реализовано.**

Новая учётная запись получает роль `user`. Роль `admin` назначает владелец через защищённый доступ к базе после проверки конкретного аккаунта. Сервер проверяет права; роль `editor` не разрешает публикацию.

Приложение использует:

- серверные сеансы в базе; cookie с `HttpOnly`, `SameSite=Lax` и `Secure` в production;
- проверку `Origin` для изменяющих запросов и ограничение частоты попыток входа;
- параметризованные запросы, очистку HTML, заголовки Helmet/CSP;
- серверную проверку ответов и защиту от повторного начисления XP;
- журнал административных действий; логи ошибок с типом ошибки и идентификатором запроса без паролей и SQL.

Локально сервер слушает `127.0.0.1`, в production — `0.0.0.0` за HTTPS-прокси. Шрифты, PDF.js и его worker поставляются вместе с приложением. Анимации учитывают настройку уменьшения движения.

## База данных и миграции

SQLite используется для локальной работы, **PostgreSQL обязателен для production**. Подготовлены три миграции:

| Файл | Изменение |
| --- | --- |
| [`001.sql`](migrations/001.sql) | Пользователи, материалы, квесты, попытки, XP, версии, аудит и сеансы. |
| [`002-postgres.sql`](migrations/002-postgres.sql) | Поисковый вектор и GIN-индекс PostgreSQL. |
| [`003-credentials.sql`](migrations/003-credentials.sql) | Учётные данные для входа по имени и паролю. |

Для проверки PostgreSQL используйте отдельную ветку Neon. В `.env` задайте `DATABASE_URL`, прямое `DATABASE_URL_UNPOOLED` и `CONFIRM_DEV_DATABASE=yes`, затем выполните:

```sh
npm run db:migrate
node --env-file=.env scripts/refresh-catalog.mjs
```

При таком импорте новые статьи PostgreSQL создаются как черновики. Полная инициализация внешнего экземпляра выполняется отдельным скриптом размещения.

API каталога использует SQLite FTS5 либо PostgreSQL `tsvector` с русским словарём и GIN. Общий пользовательский поиск `/api/search` ищет слова в текстах WebLab и локальном индексе руководства; он не использует морфологический индекс PostgreSQL.

Существующий GitHub Secret нельзя прочитать обратно для локального запуска. Передавайте подключения через `.env` или защищённые настройки хостинга, никогда через код или клиентскую сборку.

## Размещение на Railway

Настройки находятся в [`Dockerfile`](Dockerfile) и [`railway.json`](railway.json). Для завершения публикации нужно подключить репозиторий, разрешить вопрос с размещением материалов и проверить доступные ресурсы Railway. Рабочая публичная ссылка будет добавлена после успешного запуска и проверки.

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` |
| `PORT` | `8080` |
| `APP_URL` | Точный HTTPS-origin сайта без завершающего `/`; должен совпадать с адресом в браузере. |
| `SESSION_SECRET` | Постоянный случайный секрет длиной не менее 32 символов. |
| `DATABASE_URL` | Подключение Neon PostgreSQL; для приложения допустим pooled endpoint. |
| `DATABASE_URL_UNPOOLED` | Необязательное прямое подключение для миграций; для Neon скрипт умеет получить прямой hostname из `DATABASE_URL`. |
| `CONTENT_PUBLICATION_APPROVED` | `yes` после согласования публикации материалов. |
| `CONFIRM_DEPLOY_DATABASE` | `yes` после проверки целевой базы для инициализации. |

Порядок развёртывания:

1. Docker устанавливает зависимости и получает архив по [`data/content-release.json`](data/content-release.json), проверяя SHA-256. Указанный архив должен быть опубликован и доступен сборке.
2. Vite собирает клиент; итоговый контейнер запускается от непривилегированного пользователя.
3. Перед запуском `scripts/prepare-deployment.mjs` применяет миграции и добавляет отсутствующие статьи и квесты в транзакции. Существующие аккаунты, прогресс и записи контента не перезаписываются.
4. Railway запускает сервер и проверяет `/api/health`. После подключения автоматических развёртываний push в выбранную ветку может запускать этот процесс повторно.
5. Проверьте HTTPS, регистрацию, вход, смену пароля, сохранение попытки, поиск, открытие PDF и иллюстраций.

Флаги окружения — технические предохранители, а не разрешение на распространение материалов. Не включайте публикацию архива до согласования его содержимого и места хранения.

## Проверки и обслуживание

```sh
npm test
npm run build
```

Тесты охватывают авторизацию, отзыв сеансов после смены пароля, права доступа, защиту изменяющих запросов, XP и транзакции, учебные материалы, геометрию непрерывного руководства и механику игры. Проверки содержимого требуют полного локального комплекта инструкций. Тестовые базы изолированы от рабочей базы.

Для резервной копии SQLite остановите сервер и сохраните базу вместе с комплектом материалов. Не копируйте только файл активной SQLite без учёта WAL. Для PostgreSQL используйте `pg_dump` через прямое подключение и проверяйте восстановление в отдельной базе. Секреты храните отдельно от общедоступных архивов.

Откат приложения выполняется к предыдущему успешному развёртыванию. Автоматического разрушительного отката миграций нет; восстановление базы требует отдельной проверки, чтобы не потерять новые аккаунты и прогресс.

## Структура репозитория

```text
src/         Интерфейс, руководство, тренажёры и лабораторная игра
server/      API, учётные записи, работа с БД и правила начисления XP
migrations/  SQL-миграции
scripts/     Импорт материалов и подготовка размещения
data/        Квесты, метаданные источников и локальные индексы
public/      Логотип, статические файлы и локальный комплект инструкций
tests/       Автоматические проверки
```

Основной стек: React 19, Vite, Express 5, Node.js 24, PostgreSQL/SQLite и PDF.js. Визуальный стиль: неон, игровые заголовки Russo One, компактный IBM Plex Mono в учебных разделах, прозрачная лиса и надпись **BREGIS**.
